Computers your agents can fork.

Your agent gets its own computer and forks a copy for each task. You see everything the copy changed, then merge it or drop it.

Git for computers.

For high-velocity developers and small teams.

  • parallel agents

    One virtual machine per agent

    Each fork is its own VM with its own network and disk, so two agents can listen on port 3000 and run the same migration at once.

  • environment setup

    Forks boot from main's disk

    A fork starts from a snapshot of main in seconds, with the repositories you cloned and the packages you installed already on it.

  • full access

    Root in a VM with no route to your Mac

    The agent has sudo and the public internet. The VM cannot reach your Mac, your local network or your VPN, and real secrets are filled in outside it.

  • review

    A diff of the whole machine

    Silo compares a fork with the state it was forked from and groups the changes into code, packages, settings, files and databases.

  • teams

    A shared host for the team

    A team's Mac mini or Linux server builds each recipe once for everyone and shows what each member has waiting to merge.

  • where it runs

    Your Mac, a Linux server or the cloud

    The engine runs on a Mac, a Linux server with KVM or a cloud machine, and a computer takes the same commands on each.

in heavy development

Treat Silo as a build in public for now. If you try it, expect rough edges, breaking changes, no security guarantees and no data migration between versions. Don't keep anything in it that isn't backed up.
