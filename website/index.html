Git for computers.

For high-velocity developers and small teams.

  • recipes

    A recipe is built once

    A short text file describes a computer. Silo builds it once, and every computer made from it starts in seconds.

  • your tools

    Your browser, editor and terminal reach in

    Each fork's port gets its own address on your Mac, its folder opens in VS Code or Zed, and ssh reaches it by name.

  • secrets

    Secrets and tokens stay outside the VM

    The computer holds a placeholder. The real value is added outside it, only on requests to the hosts and repositories you chose.

  • network rules

    Open, limited or closed, per computer

    A computer reaches the public internet, a list of hosts or nothing, and never your Mac. Its agent can ask for another host.

  • review

    A diff of the whole machine

    Silo compares a fork with the state it was forked from and groups the changes into code, packages, settings, files and databases.

  • merge requests

    Everything waiting to merge, in one list

    A fork marked ready waits with a fresh diff. A rule can merge those where only code changed and the tests pass.

  • step history

    Go back, or fork from any step

    Every command run through Silo is a numbered step. You can restore a checkpoint or fork from the step before things broke.

  • other devices

    A computer from your server or a teammate

    An issue label or a schedule starts a task on your Linux server. Bring its computer, or a teammate's, onto your Mac to check the work.

  • linux, macos

    Linux and macOS computers on one Mac

    Your Mac hosts Linux and macOS computers side by side. Each has a screen you can open, and its agent can click through it.

in heavy development

Treat Silo as a build in public for now. If you try it, expect rough edges, breaking changes, no security guarantees and no data migration between versions. Don't keep anything in it that isn't backed up.
