Silo release film (59 seconds)

This silent film uses production Silo components with sample data and inert
backend actions. Agent sessions, the guest desktop, editor, terminal, browser
content, and computer diagrams are illustrations. No live agent, credentials,
device connections, or virtual machines are used in the film.

0:00 — Silo. A computer for your agents. Linux computers on the devices you own.
0:03 — In an illustrated agent session, the agent observes the Linux desktop, clicks Create a project, inspects the new project, and checks the result. The desktop viewer uses Silo's production component.
0:11 — Silo's overview shows local and remote computers together. A diagram links This device with Studio Mac over SSH: three computers, two devices.
0:16 — Browse a project's files in Silo while an illustrated editor updates the code. A terminal strip shows the development server starting.
0:21 — Enable SSH and network access for a computer, copy its address, and save a connection key. An illustrated coding agent uses the address and key to connect, selects /workspace/experiments, submits a prompt, and reads the remote README.
0:32 — Choose GitHub repositories for each computer. OAuth access starts read-only; the example design-system repository is read-only.
0:37 — Edit PACKAGE_TOKEN and restrict its access to the web computer and registry.npmjs.org HTTPS domain.
0:42 — Create a backup of the stopped local web computer. Silo captures and verifies the backup, then shows the saved archive in its recent backup history. The example compresses the waiting time.
0:47 — Connect the development server on Studio Mac's port 5173 in Network. Open the local forwarded address, 127.0.0.1:53124, in an illustrated browser on the laptop.
0:54 — Silo. Give your agents a space of their own. Linux computers, agent desktops, scoped access. Available for macOS and Linux at silo.amontlabs.com. Open source under the MIT license.

To connect devices, install Silo on both, enable SSH access on the owning
device, and enable Allow connections from other devices. Keep Silo running on
the owning device. The illustrated SSH connection assumes an existing network
route between the two devices.
