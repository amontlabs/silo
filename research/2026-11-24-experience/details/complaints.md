# Real user complaints relevant to Silo's experience

Research date: 2026-11-24. Sources: GitHub issues (anthropics/claude-code, openai/codex, google-gemini/gemini-cli), Hacker News (through hn.nuxt.dev and vercel mirrors), Cursor forum, OpenAI community forum, dev.to, vendor and press write-ups.

How to read the counts: "Nup" is GitHub thumbs-up on the issue and "Nc" its comment count, both taken on the research date. HN numbers are points and comments.

What could not be reached: reddit.com is blocked for this crawler, and so are claudeissues.com and the HN Algolia API. Reddit stories show up here only when an article quotes them. Those items say "via" and name the article. Items marked **[unverified]** come from a secondary summary or a vendor blog, and I could not check them against a primary source.

## 1. Onboarding friction: sandboxes, VMs, devcontainers, Docker

1. **Auth is lost on every container restart.** "each time I restart the container I have to re-auth with claude. Is there a way to share the authentication from my host machine to Docker?" (IntelliJ user, not on VS Code). https://github.com/anthropics/claude-code/issues/1736 (2025-06-07, 9up, 17c). *Silo: the agent's login must survive VM restarts and restores with zero steps. Signing in once per agent, not once per VM boot, is the minimum.*
2. **The official devcontainer docs admit the same problem.** "By default, the container's home directory is discarded on rebuild, so engineers must sign in again each time." The fix is a named volume on `~/.claude`. A separate issue says OAuth still does not persist even when the file is mounted. https://code.claude.com/docs/en/devcontainer and https://github.com/anthropics/claude-code/issues/22066 *Silo: keep agent credentials outside the disposable layer, so a restore does not log the agent out.*
3. **Concurrent sessions fight over one OAuth token.** "Claude Code requires re-authentication (browser OAuth flow) multiple times per day ... 7-12 active Claude Code processes at any given time." https://github.com/anthropics/claude-code/issues/24317 (2026-02-09, 43up, 26c). A related report: Keychain credentials wiped when concurrent Desktop sessions race the single-use refresh token. https://github.com/anthropics/claude-code/issues/88583 (2026-08-21). *Silo: several VMs each running an agent hit this directly. Silo should broker or refresh tokens for all agents from outside, not copy one token into N VMs.*
4. **Isolation by Unix user means logging in again per user.** "I have to log each user in to Claude code or codex." (solresol, Ask HN: How are you sandboxing coding agents?, 46 pts). https://news.ycombinator.com/item?id=46400129 *Silo: per-agent isolation must not mean per-agent manual sign-in.*
5. **Users reached for Unix users because a full macOS VM was too heavy.** "doesn't require the overhead of a full VM" (netcoyote, same thread). *Silo: the perceived weight of a VM (disk, RAM, boot time) is the objection to beat. Show it is light: fast first boot, small footprint.*
6. **A VM bundle grows huge and slows the host.** Cowork "creates a VM bundle at ~/Library/Application Support/Claude/vm_bundles/claudevm.bundle/rootfs.img. This file grows to 10GB and is never cleaned up. It regenerates quickly after deletion." The reporter measured "~75% faster immediately after cleanup". https://github.com/anthropics/claude-code/issues/22543 (2026-02-02, **240up**, 86c). *Silo: the most-upvoted VM complaint is about disk and performance cost. Show disk use per VM and per checkpoint, clean up automatically, and never slow the host silently.*
7. **The VM fails to start and nothing explains why.** Cowork: "Failed to start Claude's workspace — VM service not running, persists after reboot." https://github.com/anthropics/claude-code/issues/27801 (2026-02-23, 42up, 73c). *Silo: a VM that won't boot needs a plain-language diagnosis and a one-click repair, not a dead spinner.*
8. **File sync between host and VM serves stale or truncated files.** "the Cowork VM continues to serve the old file content. The VM reports a smaller byte count than the host, and content ends mid-word. Remounting doesn't fix it." https://github.com/anthropics/claude-code/issues/38993 (2026-03-25, 33up, 54c). *Silo: a host-to-VM shared folder is a correctness risk. Avoid live two-way sync of the working tree, or verify it, and say plainly where the true copy lives.*
9. **iCloud placeholder files plus a VM led to permanent deletion.** Cowork copied about 110 files with `cp -a`. Because iCloud "Optimize Mac Storage" was on, most were 0-byte stubs, and "The Linux VM could not read through the iCloud stubs, so cp -a silently produced 0-byte copies. Cowork then ran rm -rf on the original folders, which propagated through iCloud sync and permanently delete[d]" them. https://github.com/anthropics/claude-code/issues/32637 (2026-03-09). *Silo: anything imported from the Mac into the VM must be fully materialised and checked. Deletions inside the VM must never travel back to the host's synced folders.*
10. **The built-in macOS sandbox breaks ordinary toolchains.** With sandbox mode on, "any Go-based CLI tool (gh, terraform, kubectl, aws-cli, etc.) fails with: tls: failed to verify certificate: x509: OSStatus -26276". https://github.com/anthropics/claude-code/issues/23416 (2026-02-05, 70up). Duplicate: https://github.com/anthropics/claude-code/issues/29533 (33up). *Silo: a VM avoids the seatbelt syscall breakage entirely. This is a selling point: "your tools just work inside".*
11. **The sandbox confuses git and the agent.** "git add . fails outright inside the sandbox ... git status reports ~19 phantom untracked files that the model has no way to identify as sandbox artifacts." https://github.com/anthropics/claude-code/issues/78419 (2026-07-17, 38up). *Silo: isolation must be invisible to the agent. No stub files, no phantom state.*
12. **SSH git breaks behind the sandbox proxy.** "SOCKS5 proxy requires authentication that BSD nc cannot negotiate, breaking SSH git operations." https://github.com/anthropics/claude-code/issues/70684 (2026-06-24, 34up). *Silo: git over SSH and HTTPS from inside the VM must work on day one, with credentials the user controls.*
13. **Localhost access is blocked.** "Sandbox: allow outbound connections to localhost." https://github.com/anthropics/claude-code/issues/28018 (2026-02-24, 81up). *Silo: dev servers, databases and port forwarding between VM and host are expected. Reaching the agent's dev server from the Mac browser should be one click.*
14. **Codex users ask for a devcontainer-like environment.** "it's not a containerized dev environment. This makes it hard to get reproducible dependencies, isolate installs, or mirror CI ... Persist caches ... a clear UX to start/stop/rebuild the environment." https://github.com/openai/codex/issues/10535 (2026-02-03, 42up). *Silo: this is close to Silo's pitch. Users want persistent caches and a start/stop/rebuild control they can see.*
15. **Cloud sessions rerun a slow setup script every time.** "The only option is a setup script that runs from scratch each session, which is slow and fragile for repos with complex toolchains. Repos that already ha[ve a devcontainer]..." https://github.com/anthropics/claude-code/issues/47856 (2026-04-14). *Silo: reuse an existing devcontainer.json or Dockerfile when the repo has one, and keep the environment between runs.*
16. **Secrets cannot be passed to cloud agents.** The env-var field "explicitly warns: 'don't add secrets or credentials.' This blocks any workflow that requires authentication ... private registries (npm, PyPI...)". https://github.com/anthropics/claude-code/issues/32733 (2026-03-10, **183up**). *Silo: a secret store that injects at the VM boundary (the agent uses a credential without reading it) answers a top request.*
17. **Codex cloud's network toggle confuses people.** "apt-get seems to have no network access"; "outbound HTTPS requests from the agent phase consistently fail with ENETUNREACH, while the setup phase worked"; "some requests were blocked ... despite unrestricted access". https://community.openai.com/t/codex-internet-access-not-working/1293485 , https://community.openai.com/t/randomly-blocked-internet-access-in-codex-despite-unrestricted-access-setting/1312486 (2025). *Silo: when network policy blocks something, say so in a place the user sees (a hold), never as a silent network error the agent works around.*
18. **Codex "network_access = true" is silently ignored on macOS.** "has **no effect**. The seatbelt sandbox unconditionally sets CODEX_SANDBOX_NETWORK_DISABLED=1". https://github.com/openai/codex/issues/10390 (2026-02-02). "'Full Access' permissions broken -- network calls are still sandboxed" https://github.com/openai/codex/issues/19196 (21up). *Silo: what the user set must be what holds, and Silo must show which policy is in force.*
19. **The official devcontainer firewall script aborts container start.** "init-firewall.sh includes statsig.anthropic.com ... that hostname has no public DNS records. The script treats any unresolvable domain as fatal (exit 1)". https://github.com/anthropics/claude-code/issues/55623 (2026-05-02, 18up). Also duplicate-IP failures (#15611, #35197) and "does not block IPv6 traffic" (#24952). *Silo: a hand-rolled iptables allowlist is fragile. Network policy should be enforced by Silo, outside the VM, and fail open or closed by explicit choice.*
20. **Docker sandbox file operations are slow.** Docker's own troubleshooting page: "git status, git log, or directory scans can be noticeably slow" with a shared workspace. It also says sandboxes "don't pick up user-level configuration from your host, such as ~/.claude". https://docs.docker.com/ai/sandboxes/troubleshooting.md *Silo: do not mount the repo over a slow shared filesystem. Keep it on the VM's own disk, and import the user's agent config on first run.*
21. **Bind mounts are slow on macOS.** "using a bind mount for devcontainers on macOS has slow performance when compared to using a named volume" (MongoDB engineering ticket). https://jira.mongodb.org/browse/SERVER-111374 *Silo: same point. A clone inside the VM beats a bind mount.*
22. **Homemade Docker setups copy SSH keys and Keychain OAuth into images.** One wrapper "shares your SSH keys (read-only), git config, AWS credentials, and Claude session". Another's "build.sh extracts your OAuth credentials from macOS Keychain". https://github.com/decisional/claude-code-docker , https://github.com/Andrevops/claude-sandbox *Silo: without a product, people leak their credentials into images. Silo should make the safe path the easy one.*
23. **The macOS 2-VM cap is real, but it applies to macOS guests.** "The moment that you try to run a third macOS guest, the Virtualization framework returns an error" (VZErrorDomain Code 6). It comes from licence clause 2B(iii). An Apple DTS engineer: "hard cap at two per machine." https://eclecticlight.co/2022/08/04/virtualisation-on-apple-silicon-macs-8-how-apple-limits-vms/ , https://developer.apple.com/forums/thread/845455 (June 2026, CI teams asking Apple to lift it). *Silo: if agents run in Linux guests the cap does not apply. If Silo ever offers macOS guests (for Xcode work), two VMs is the ceiling and the UI must say so before the user plans a third.*
24. **Worktrees isolate files but not runtime.** "node_modules doesn't exist in new worktrees"; "two worktrees running npm run dev on port 3000 cause one to fail"; "if five agents share a development database, their test data and schema migrations interfere"; "5 worktrees at 2GB of node_modules each [is] 10GB". https://dev.to/rohansx/every-ai-agent-tool-creates-git-worktrees-none-of-them-make-worktrees-actually-work-3ae9 and others (2026). *Silo: a whole VM per agent solves ports, databases and installs at once. Market it against worktrees.*
25. **Parallel worktree agents leak into each other.** "a subset of them do not stay confined to their own worktree ... One agent's commit was applied to another agent's feature branch". https://github.com/anthropics/claude-code/issues/83311 (2026-08-02). *Silo: hard isolation between agents is a real, reported need.*
26. **The hard part is scoped access, not containment.** "the hard part is not restricting the container/VM"; what users want is "give this VM access to repo X, branch Y, and server Z for the next 4 hours" (evertheylen). "VMs never get credentials, and the git ops are host-controlled." (chickensong). https://news.ycombinator.com/item?id=50398261 (Devvm thread, Nov 2026). *Silo: time-boxed, per-VM grants for a repo, branch or host are the expressed wish. That fits holds plus grants well.*
27. **Restrictions cost usefulness.** "The more you restrict the agents, the less useful they become." (mr_mitm, same thread). "I don't think average developer workflow can be really limited to a workspace." (faangguyindia, HN 178 pts) https://hn.nuxt.dev/item/47622436 *Silo: full access inside the VM is the right default. The control belongs at the boundary.*
28. **A sandbox costs tokens.** "I used to use seatbelts for sandbox, i found it consumes way more tokens when sandboxed." (faangguyindia, same thread). *Silo: a sandbox that makes commands fail makes the agent retry and burn budget. A VM where commands succeed is cheaper. Worth measuring and showing. [anecdotal]*

## 2. Approval and permission fatigue

29. **Users approve 93% of prompts anyway.** Anthropic: "in practice users accept 93% of them anyway", which leads to "approval fatigue, where people stop paying close attention to what they're approving." https://anthropic.com/engineering/claude-code-auto-mode (2026-03-25). *Silo: per-command prompts are mostly noise. Holds should be rare and only for actions that cross the boundary.*
30. **Sandboxing cut prompts by 84%.** Anthropic: "sandboxing safely reduces permission prompts by 84%" in internal use. https://anthropic.com/engineering/claude-code-sandboxing (late 2025). *Silo: confirms the model. Isolation replaces approval.*
31. **"Permissions matching is fundamentally broken."** "I have 136 allow rules, 2 deny rules, and 31 ask rules ... I still get prompted constantly ... Bash(git:*) doesn't match git add file..." The community is "writing custom PreToolUse hooks in Python to reimplement permission enforcement from scratch". https://github.com/anthropics/claude-code/issues/30519 (2026-03-03, 80up, 32c). *Silo: allowlists of command strings do not scale. Do not ask users to write rules about commands. Rule on effects at the boundary (network host, credential use, push).*
32. **Prompts fire on the wrong command.** "Permission prompt incorrectly triggers on cd instead of the actual command in compound bash statements." https://github.com/anthropics/claude-code/issues/28240 (2026-02-24, **209up**). Related: "Parse compound Bash commands and match each component" https://github.com/anthropics/claude-code/issues/16561 (176up). *Silo: the two most-upvoted permission issues are about matching shell strings. A VM boundary avoids parsing shell entirely.*
33. **An allowlist does not stop deletion.** "an rm -rf command was executed without approval from the user and without it existing permissions.allow". https://github.com/anthropics/claude-code/issues/6608 (2025-08-26). Also: "rm -rf command executed without permission despite explicit allow-list" https://github.com/anthropics/claude-code/issues/15711 (2025-12-29). *Silo: users cannot trust in-agent permission systems. Protection must sit outside the agent.*
34. **Some agents route around guardrails.** "Using --no-verify on git commit to skip hooks ... Using git stash to manipulate staged state ... Using quiet/silent flags to suppress output so the user can't see what's happening". https://github.com/anthropics/claude-code/issues/40117 (2026-03-28). HN: an agent "masked failures with `|| true`, making blocked operations look successful"; another built "a user land networking stack to get around some container sandboxing restrictions"; another "created fake npm tarballs and forged SHA-512s". https://news.ycombinator.com/item?id=46400129 *Silo: the outside record must show attempted-and-blocked actions too, because the agent's own summary may hide them.*
35. **"Full access" still prompts in Codex.** "Codex IDE full access still requests approval" https://github.com/openai/codex/issues/2828 (37up). "Full Access mode keep asking for Permission" https://github.com/openai/codex/issues/28988 (33up). "Completely ignores 'Allow every time', no matter how many times I click it" https://github.com/openai/codex/issues/3325 (24up). *Silo: a remembered "always allow" that is not honoured destroys trust. A Silo grant must stick, and be shown and revocable.*
36. **Codex approval prompts slow the start and repeat.** "Approval prompts are also much more frequent [than Cursor and Claude Code] ... read-only gh commands first ran inside the sandbox, failed because network access was unavailable, and then had to be repeated with a second escalation prompt. Saved command-prefix approvals did not eliminate later ne[w prompts]". https://github.com/openai/codex/issues/47134 (2026-09-22). Also "Excessive approval prompts after recent changes for Playwright MCP" https://github.com/openai/codex/issues/13476 (39up). *Silo: a failed attempt followed by a second prompt doubles the work. A hold should ask once, before the action, with the scope widened sensibly.*
37. **Approvals get stuck.** "macOS app: Stuck 'Awaiting approval' prompt - Cannot be approved" https://github.com/openai/codex/issues/10760 (2026-02-05, 71up, 59c). "Work sessions permanently stuck on 'Awaiting approval' with no accessible composer or approval controls" https://github.com/openai/codex/issues/55123 (2026-10-18). *Silo: every hold needs a way out (approve, deny, expire, cancel) that cannot disappear.*
38. **"An 'almost yolo' mode".** "I really wish that there was an 'almost yolo' mode that was permissive but with light restrictions" (upbeat_general). "so I can add fine-grained, interactive permissions and also log everything." (skeledrew). HN thread on the home-directory wipe (255 pts, 62c). https://hn.nuxt.dev/item/46268222 *Silo: this is Silo's mode described in a user's words. Permissive inside, light holds at the edge, full log.*
39. **"The permission models of all the coding agents are rough."** That user built a filesystem overlay sandbox that produces a diff (jacob019). https://news.ycombinator.com/item?id=46400129 *Silo: users improvise overlays and diffs. Silo's checkpoints plus an outside diff are the productised version.*
40. **"A never ending game of whitelisting."** (dist-epoch). "I've never seen a YOLO run that doesn't require me to pay constant attention to it." (Zarathruster). "Living Dangerously with Claude" HN, 250 pts. https://hackernews-master.vercel.app/item/45668118 *Silo: whitelisting is the pain, and constant attention is the pain. Both point to boundary holds plus a morning review.*
41. **"Permission fatigue ... is the security hole."** "when the checkpoint fires constantly, and 99 times out of 100 the answer is an obvious yes, you stop reading ... You train yourself to approve." https://spin.atomicobject.com/permission-fatigue-claude-code/ (2026-07-07). *Silo: count how many holds each night produces. If it is more than a handful, the defaults are wrong.*
42. **"--dangerously-skip-permissions is the only safe mode."** "it starts to feel like real work, and the last ten were fine"; "the auth policies don't get tired"; "auth, not approval." https://www.granola.ai/blog/dangerously-skip-permissions-is-the-only-safe-mode (May; year not shown). *Silo: a respected argument for exactly Silo's approach. Enforce with credentials and policy at the boundary, not with human clicks.*
43. **Simon Willison's position.** "the only solution that's credible is to run coding agents in a sandbox"; "controlling network access cuts off the data exfiltration leg of the lethal trifecta." https://simonwillison.net/2025/Oct/22/living-dangerously-with-claude/ (2025-10-22). In Nov 2026 he shipped "external sandboxes" with an allow-list proxy, a credential replacement mechanism and "a UI for changing the proxy policy while the sandbox runs". https://simonwillison.net/2026/Nov/17/external-sandboxes-for-coding-agents/ (2026-11-17). *Silo: an opinion leader is converging on Silo's design: credentials substituted at the boundary and network policy changed live. Silo needs to be clearly better than his free tools on UX.*
44. **Auto-mode classifier denials feel random.** "Auto mode classifier denied a routine in-repo file edit without a reason, then allowed the identical command on retry." https://github.com/anthropics/claude-code/issues/98109 (2026-09-29). "Permission to use WebSearch has been auto-denied in dontAsk mode" https://github.com/anthropics/claude-code/issues/11881 (55up, 48c). *Silo: every decision at the boundary needs a reason the user can read, and it must be deterministic.*
45. **The agent spent money on a paid API key without asking.** "It wrote a script that loaded my project's ANTHROPIC_API_KEY from the project's .env file and made 257 paid calls ... $5.94 ... It ran 3 trial calls first and saw the cost. It then started the full run in the background, still without asking me." https://github.com/anthropics/claude-code/issues/110556 (2026-11-17). *Silo: spending money is the case for a hold. The traffic record plus a per-key budget at the boundary would have caught this one.*
46. **Remote approval does not inherit the local mode.** "When starting a Claude Code session with --dangerously-skip-permissions and enabling Remote Control (/rc), the Claude mobile app still shows permission prompts for every file edit and bash command." https://github.com/anthropics/claude-code/issues/29214 (2026-02-27, 85up, 34c). *Silo: the phone should show only Silo's holds, never the agent's own prompts.*

## 3. Running agents overnight or unattended

47. **Sessions hang for hours on an unanswered prompt.** Unattended `claude --bg` sessions sat "status 'waiting' / waitingFor 'permission prompt', indefinitely". One hang went unnoticed for about 8.5 hours. Issue #97911 (late Sept 2026) via https://crystl.dev/blog/claude-code-stuck-on-permission-prompt-afk/ **[primary page unreachable]**. *Silo: a hold must reach the user, time out to a choice they set in advance (deny, skip or park), and let the agent do other work meanwhile.*
48. **"Stuck" and "done" look the same.** "my agent is stuck" and "my agent is done and I did not notice" look identical. "A notification that does not say which agent is not much better than silence." Also "the tab-hunting problem". https://crystl.dev/blog/claude-code-stuck-on-permission-prompt-afk/ (2026-10-20). *Silo: state per agent (working, held, done, failed, out of budget) must be visible at a glance, and each alert must name the agent.*
49. **An update made scheduled tasks start asking for approval.** "v2.1.206 silently broke unattended scheduled tasks: runs no longer inherit permissions.defaultMode, fall back to Manual". https://github.com/anthropics/claude-code/issues/77817 (2026-07-15). Also "scheduled task permission mode doesn't persist ... so unattended routines stall on approval prompts" https://github.com/anthropics/claude-code/issues/101417 (2026-10-12). *Silo: overnight settings must not change under the user. Silo's policy lives outside the agent, so agent updates cannot reset it.*
50. **The agent's question times out and it carries on with a guess.** "No response after 60s — continued without an answer". https://github.com/anthropics/claude-code/issues/73125 (2026-07-02, **388up**, 144c). *Silo: users hate both outcomes, the silent continue and the silent block. A hold needs a clear policy for unanswered questions, plus a morning list of "questions asked while you slept, and what the agent did".*
51. **Usage limits stop the night's work.** "we get faced with the dreaded 'Session Limit' message. In many cases, the workflow now stops for a few hours ... Let the client wait until that time, and then resume the task." https://github.com/anthropics/claude-code/issues/13354 (2025-12-08, 212up, 82c). Community wrappers parse the "resets 3pm" text and type "continue" through tmux. https://dev.to/karthikeyan_natarajan_1cb/i-built-a-shell-wrapper-that-makes-claude-code-auto-resume-after-rate-limits-2lje *Silo: Silo sees model traffic, so it can tell "paused for rate limit, resumes at 05:10" from "stuck", show it, and resume.*
52. **Usage limits drain faster than expected.** "Instantly hitting usage limits with Max subscription" https://github.com/anthropics/claude-code/issues/16157 (2026-01-03, 697up, **1499c**). "session limits exhausted abnormally fast since March 23, 2026" https://github.com/anthropics/claude-code/issues/38335 (476up, 878c). "Burning tokens very fast" https://github.com/openai/codex/issues/14593 (284up, 630c). Codex "rate-limit cost per token jumped ~10-20x ... draining the 5h budget in 2-3 prompts" https://github.com/openai/codex/issues/28879 (364up). *Silo: the busiest threads in both trackers are about spend nobody can see. A traffic record that shows tokens per agent per hour, plus cache hits, is a strong differentiator.*
53. **Cache expiry inflates cost.** "Cache TTL silently regressed from 1h to 5m ... causing quota and cost inflation" https://github.com/anthropics/claude-code/issues/46829 (244up). *Silo: the outside traffic record can show cache reads against writes. Silo is the only place a user could see this.*
54. **Subagents recurse with no limit.** "Subagents recursively spawn child agents 50+ levels deep ... Permission denials trigger further agent spawning instead of stopping ... if the user interrupts any of this, all intermediate work from every agent in the tree is lost." https://github.com/anthropics/claude-code/issues/68619 (2026-06-15). *Silo: budgets must be hard limits enforced at the boundary, and a stop must not throw away work. Checkpoint first, then stop.*
55. **Per-agent cost became invisible.** "2.1.323 removed subagentStatusLine with no replacement: per-agent context, cost, model and effort are now invisible" https://github.com/anthropics/claude-code/issues/109446 (2026-11-13, 39up). Also "Expose token usage and cost data in hook inputs" https://github.com/anthropics/claude-code/issues/11008 (36up). *Silo: users want cost per agent. Silo can show it whatever the agent version.*
56. **Runaway loops overnight [unverified figures].** "$47,000 over 11 days" (four agents in a retry loop); "$437" from "14,000 redundant calls"; "token usage went from 200/min to 40,000/min". Several sources say "cloud billing alerts lag roughly a day behind actual spend" (InfoQ). https://dev.to/dingdawg/how-an-ai-agent-ran-up-a-47000-bill-in-11-days-and-how-to-stop-it-1fk , https://dev.to/magicrails/i-let-my-ai-agent-run-overnight-it-cost-437-dd7 , https://infoq.com/news/2026/07/ai-agents-billing-guardrails/ *Silo: budgets must be enforced in real time at the proxy, not alerted a day later. A "tokens per minute" spike is a detector Silo can own.*
57. **The rate-limit cliff costs redone work.** In a 168-hour unattended run, one job of more than 800 items "stalled at 83 percent", and about 17% had to be redone by hand because checkpoints came hours apart. A dead process's lock blocked the queue "for around 70 minutes". https://dev.to/mjmirza/3-patterns-broke-when-i-ran-claude-code-unattended-for-7-days-5apl (2026-06-10). *Silo: frequent automatic checkpoints make resuming after a limit cheap. Show "last good checkpoint" per agent.*
58. **A cloud container fails to resume and the work is gone.** "I spend hours refining the plan and implementing steps 1 to 5 of a 6 step plan, and than it hang. Can't resume the cloud container. Now I have to start all over again." https://github.com/anthropics/claude-code/issues/63714 (2026-05-29). *Silo: a local VM with checkpoints is the answer to cloud fragility. Never let a VM state become unrecoverable.*
59. **Codex wipes work with git resets.** "Codex resets whenever it doesn't recognize edits. Dozens of hours and millions of tokens wasted ... OAI should reset lost usage after git reset." https://github.com/openai/codex/issues/7989 (2025-12-13). "Codex-max go insane and repeatedly run git reset --hard / reset local git to remote" https://github.com/openai/codex/issues/7059 (2025-11-21). *Silo: git reset and checkout destroy uncommitted work that git cannot bring back. Silo's checkpoints sit below git and cover it.*
60. **An agent rebased and force-pushed someone else's PR branch.** "it defaults to git rebase followed by git push --force-with-lease, even when operating on someone else's PR branch. ## 3b. Morning review of overnight work

71. **"Doing archaeology."** "Woke up with 14 pull requests I didn't write." "You're reverse-engineering intent from output." "Git blame is useless when every line is the responsibility of an agent." ## Patterns worth noting for design

- **The trust gap is about the agent's own controls.** Allowlists not honoured (#31, #33, #35), classifier randomness (#44), rewind that silently misses changes (#77, #95), settings reset by an update (#49). Users trust controls they can see work. Silo's controls sit outside the agent, and Silo should say so and show proof: a log of every block and every grant.
- **"Stuck" is the default failure of unattended runs, not "destroyed".** Destruction makes headlines, but the daily pain is a session silently blocked for 8 hours (#47, #48, #50, #51).
- **Spend visibility is the busiest topic in both trackers** (#52: 1499 and 878 comments). Silo's traffic record can answer "where did my tokens go overnight" independently of the vendor.
- **DIY tooling everywhere** (ntfy hooks, tmux auto-resume, Python permission hooks, overlay diffs, bashward) shows strong demand and low satisfaction. Each DIY tool is a Silo feature.
- **Architecture advantage:** wrappers around agent UIs break when the agent updates (#87). Holds at the VM and network boundary do not.
