# What a drop would lose

## The choice

An agent's part, 22 November 2026. You drop the fork where an agent tried Node 24. Silo shows two
things only in it: a commit on the branch `node-24` that was never pushed, and `notes.md`, which the
agent wrote in your home folder. You push the commit, copy `notes.md` to main, and drop the fork.

The options:

- Build it (recommended). Before each drop you see what only the fork holds and save what you want,
  through Git or by copying files. When the list is empty, Silo says the drop loses nothing, as its
  opinion. It costs one more screen before a drop, and an empty list is an opinion, not a promise.
- Leave it out. A drop sends the fork to the bin without a look. It costs what was only in it, once
  its time in the bin ends.

Recommended: build it. A drop is one click, and the one file nobody remembered is the usual loss.
