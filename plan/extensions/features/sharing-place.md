# A place to share

## The choice

An agent's part, 22 November 2026. You wrote rules that let a computer reach the npm registry and
its mirrors, and an extension that watches for runaway builds. Another Silo user wants both. Today
you would send them a link to a Git repository. With a place to share, they find both by name and
import them from there.

The options:

- Build it (recommended). It can start as a list on Silo's site of Git repositories that hold
  recipes, rules and extensions, each imported by its address. It costs someone looking at what is
  listed, since a listing lends it Silo's name.
- Leave it out. People share through Git hosts and links. It costs finding things: each user writes
  again what someone else already wrote.

Recommended: build it, as a list first. The Dev Containers project lists its features this way, and
since importing changes nothing and shows everything, a listed extension still shows all it may do
before it can do it.
