# The explanation in an ask

## The choice

An agent's part, 27 November 2026. The transaction guard holds a transaction because its
simulation shows 2 ETH leaving your account for an address you never used. `what-an-ask-shows`
writes an ask from facts: the computer, the host, the secret. What the simulation found is what
you need in order to answer, and it has no place in the ask. An opinion takes its value from a
list Silo fixes (`who-fixes-the-values`), and a balance is in no list. `opinion-is-a-value` lets
an opinion carry an explanation in words, which the app shows as untrusted text.

The options:

- The ask shows the explanation, as the extension's words (recommended). The value of the opinion
  stays in Silo's list. The ask keeps Silo's facts and the extension's words apart, as it does for
  what the agent says. It costs text from someone else's code in front of you at the moment you
  decide.
- The value only. The ask says "held by transaction-guard". It costs the reason, and you open a
  panel to find it while the hold runs out.
- The extension writes the ask. It costs the facts, since an ask could then say anything.

Recommended: the ask shows the explanation, as the extension's words. No rule and no precaution
reads it, as `opinion-is-a-value` says. A threshold, such as how much may leave, lives in the
extension. Whether the computer sees the explanation follows `reason-in-a-refusal`: by default it
learns only that the request was denied or held.
