# Logins kept out of copies

## The choice

An agent's part, 22 November 2026. Claude Code is signed in on main with your subscription. You fork
main to let an agent try a tool you do not trust yet. The fork starts without the login, and you
sign in there only if you want Claude Code in it.

The options:

- Build it (recommended). A fork, or a computer you share, starts without the logins your agent
  programs keep, unless you or a rule you set let one through. It costs a sign-in in each fork that
  needs one. For a program Silo does not know, it cannot find the login, so Silo says before the
  fork is made that it may be copied. On a macOS computer Claude Code keeps its login in the
  keychain, and how Silo leaves out one item of it is still to find out.
- Leave it out. A fork carries every login, as it carries the rest of the disk. It costs a promise
  in force, that a login does not end up in a fork by accident, which would have to change.

Recommended: build it. It keeps a promise in force, and a fork is where you put the agent you trust
least.
