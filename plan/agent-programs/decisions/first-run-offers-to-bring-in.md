# What first run does with what is already on the Mac

## The choice

An agent's part, 22 November 2026. On your Mac, Claude Code has three MCP servers, one of them with
your Linear API key in its settings. ~/code holds twenty repositories, one with a .env file that
holds a database password.

The options:

- Offered one by one (recommended). The first run lists each program, setting, skill and repository,
  and you tick what comes in. The Linear key can become a Silo secret, and the .env file stays on
  your Mac unless you tick it. Your logins never come in. It costs a list to go through on the first
  run. It also costs Silo the work of knowing where each agent program keeps its settings and
  skills, and of keeping up as vendors change them. A program Silo does not know is not found, and
  you bring it in by hand.
- All at once, with one yes. Everything Silo finds comes in. It costs what you would have kept out:
  a client's repository, an old skill, or a key in a setting, now in a computer where agents have
  full access.
- You move in yourself. Main starts without your setup, and a guide says how to install each program
  and copy its settings. It costs you that setup, program by program, before the first agent works
  in main.

Recommended: offered one by one. Main is where agents have full access, so what goes into it should
be what you chose. You asked for good onboarding, and the first agent in main should work with what
it had on your Mac.

## Notes

The owner said this: everyone has their own agent programs, providers and habits; how does all of it
work inside their Silo computers? The owner wants good onboarding for it.

Whether main copies from the Mac or starts from a guided recipe is open:
`main-from-the-mac-or-a-recipe`.
