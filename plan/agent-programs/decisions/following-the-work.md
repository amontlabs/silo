# What the user's app shows when work moves to a fork

## The choice

An agent's part, 22 November 2026. You talk to Claude Code in main from the Claude desktop app. An
agent's work moves to a fork, try-bun, and the desktop app stays connected to main.

The options:

- Silo's window shows all the work (recommended). The desktop app stays where you talk to one agent
  in one computer. Silo's window lists the work of every computer, whichever agent program did it,
  and one action opens the fork. It costs you a switch of window when work moves.
- Silo makes the agent app follow. Silo adds the fork to the desktop app and opens the conversation
  there. It costs relying on what the apps do not document: no app documents a way for another
  program to add a machine, so each update of the app can break it.

Recommended: Silo's window shows all the work. No product today moves a conversation's window from
one machine to another, and the tools people praise for following many agents show the work, not the
machines.

## Notes

A conversation lives in one computer. Where it continues after a fork is `conversation-taken-up-again`, in `going-back`.

## What the research of 18 November 2026 found

- No product moves a conversation from one machine to another. In every one, a conversation stays
  on the machine where it started, and the window attaches to it there.
- The tools people praise for following many agents show a list of pieces of work, and which one
  needs the user. They do not show a list of machines.
