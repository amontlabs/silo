# May an agent ask for a fork or a fresh computer

## For the owner

An agent's part, 22 November 2026. An agent in main has changed your app. It wants to run the tests
on a clean Linux computer, and to try a risky migration in a fork of main, without waiting for you.

The options:

- Yes, with no more than it has (recommended). The agent makes the fork and the Linux computer
  itself. Neither gets a secret, a login or a rule main does not have unless you say yes, and what
  they spend counts against main's budget. It costs room on your Mac: a Mac runs only a few
  computers, and with main on macOS the fork takes the one other macOS computer Apple allows. When
  the Mac is full, the agent is told no, with the reason.
- Only with your yes each time. Silo asks you before an agent makes a computer. It costs a wait for
  you each time, so the tests run only when you are there.
- No. Only you make computers. It costs the agents the clean machine and the risky try: they do both
  in main, or wait for you.

Recommended: yes, with no more than it has. Your agents already get everything you could do in the
app, and a computer with no more than main gives them nothing new.

## Notes

No answer is put forward. How the agent's work there reaches the user is
`agent-made-computer-work`.

## What is known

- An agent that starts with no app connected has nobody to hand it a login. It needs a sign-in
  done inside the computer, or an API key.
