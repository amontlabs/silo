# Processes in the record

## The choice

An agent's part, 22 November 2026. At 3 in the morning main's processor is at full use. You want to
know which command it is, what started it, and how it ended.

The options:

- Build it (recommended). The commands a computer ran are in the record, each with its parent and
  how it ended. They are told by a part of Silo inside the computer, so they are reports, and an
  agent with full access can interfere with them. It costs that small part running in every
  computer, and on macOS the list may only be sampled, which is still to find out.
- Leave it out. The record holds files and connections with no command behind them. It costs knowing
  which run did what, stopping a run, and the timeline: nine features need it.

Recommended: build it. Files and connections with no command behind them answer only half of what
happened.

## An agent's notes (21 November 2026)

From the owner's list of smaller features, where most are extensions (`what-ships-with-silo`).

- For `stopping-a-run`, `memory-and-cpu-per-run` and `stuck-run-alert`, the record needs, per run,
  the tree of processes it started and the memory and CPU each used over time. The command and
  parent are already here; the use over time is not. Without it these can only be guesses, and
  extensions that others write cannot build them.
