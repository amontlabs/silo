# A plugin is a program with a declaration

The owner said this. That the user accepts the declaration at install and Silo enforces it
afterwards is put forward on its own: `declaration-is-enforced`. The standard names are a
manifest, and permissions.

| The declaration says | Meaning | Example |
|---|---|---|
| wakes on | what makes it run | a tool call waiting at the boundary; another plugin's opinion |
| is given | its input | what the user asked the agent, and the tool call |
| runs | in Silo, or in a computer of its own | in Silo: it is data |
| may use | which of Silo's calls | read the conversations of main; give an opinion |
| gives back | the shape of its output | safe, not safe or unsure, with a reason |
| proposes | rules and precautions | "on not safe: deny" |

The owner's list for the interface of an added piece: what it receives, what it can fetch from
Silo, how it hooks in, how it sends things outside or into the app, and extra tools it brings.

The owner's word "triggered" in the answer is the one `wakes-on` would replace for a plugin.

An older text called a plugin a package through which pieces made by someone else arrive. That is
not carried: what it brings is now said by the declaration.
