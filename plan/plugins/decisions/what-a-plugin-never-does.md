# What a plugin never does

## The owner's words (21 November 2026)

- The statements that actually mean plugin are fixed to say plugin.
- On "An added classifier can never act on a computer, answer an ask, set or change a rule or a
  precaution, give a secret, or write into another computer": the owner did not understand why, nor
  where it comes from.
- On "No tool a plugin can use grants or destroys": "basically perfect". The owner's reason: what
  happens inside a computer is considered hostile, so things are settled with rules at the
  boundary, and precautions and the rest are added for convenience. The same choice is made for
  plugins: the list of tools they can reach is limited by design, which makes them secure and
  predictable.

## An agent's notes

- The older sentence listed what is forbidden without its reason, and mixed two things. The law:
  a plugin can be wrong, or tricked by text an agent wrote, so nothing it can use grants or
  destroys. A choice: a plugin does not pause or deny by itself either. The owner has not ruled on
  the choice. It belongs to the design of how a plugin fits in.
- A take changes the two properties, which say "an added classifier" and "a classifier" today. The
  page of the part `plugins` names them by id and changes with them.
