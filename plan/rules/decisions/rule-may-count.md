# A rule that counts

## The choice

An agent's part, 27 November 2026. Spend and budgets ship as an extension
(`spend-and-budgets-ship-as-an-extension`). `budget-rule-or-precaution`, taken, makes a budget a
rule where the boundary can see the tokens, so that it is exact. The notes of the first entry say
what is missing: "a manifest that can carry rules on model calls and a price table, which no entry
describes yet". A rule today allows, holds or denies one request by what that request is. A budget
needs the sum of what came before.

If a rule cannot count, the budget extension has to be asked on every model call. Its answer is
then an opinion with a time limit (`extension-that-does-not-answer`), the budget becomes a
precaution, and it is no longer exact.

The options:

- A rule may count facts (recommended). The sum is made of facts and the table is data, so
  `rule-reads-only-facts` holds. The same rule serves a limit on bytes sent to a host, or on
  requests per hour. It costs one more thing a rule can express, and the admission of a model
  call under a budget (`what-a-budget-promises`) stays code of the core.
- The extension is asked on each call. It costs the exact budget.
- Budgets go back into the core. It costs the ruling polarzero just made.

Recommended: a rule may count facts.

## To find out

How a table in a rule's data is replaced. A changed file is a new version of the extension, to
import and install again (`extension-registration`), and prices change often. Lowering a price
lets more calls pass, so it is granting, and no tool of an extension may do it.
