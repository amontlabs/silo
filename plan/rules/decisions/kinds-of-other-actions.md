# The kind of the other actions the design names

## The choice

An agent's part, 22 November 2026. A classifier is sure a fork's work is good, and main's disk is
nearly full. The question is whether a precaution could copy the fork's files into main, or empty
the bin, by itself.

The options:

- As filed (recommended). Bringing a computer back from the bin, copying a fork's files into its
  parent, and giving an extension the tool that forwards alerts and asks are granting. Purging
  files, putting back paths, removing a checkpoint, emptying the bin, leaving paths out of
  checkpoints, and removing content from the record's store at its size limit are destructive. So
  each of them needs you or a rule, and no opinion can do any of them. A copy into main first saves
  main's own versions of the files it replaces. It costs the disk those saved versions take, and a
  classifier that is right still waits for you or a rule.
- A copy into the parent as protective. Since the copy saves main's versions first, it erases
  nothing, so a precaution could bring a fork's files into main on an opinion. It costs main's
  limits: a fork with an open network can fetch what main's rules deny, and an opinion that can be
  wrong would carry it into main.

Recommended: as filed. Main should get from a fork only what you or a rule let in, and nothing
should be erased on an opinion.

## Notes

Whether forwarding alerts and asks is one of an extension's tools is open in `extensions`
(`forwarding-tool`). Forwarding to a phone is a later feature there: `forwarding-to-a-phone`.
