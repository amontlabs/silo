# How a rule is kept from acting on an opinion by a detour

## For the owner

An agent's part, 22 November 2026. A precaution denies five connections from main in one minute, on
a classifier's opinion. You also have a rule: five denied connections in a minute, stop the
computer.

The options:

- A rule ignores what a precaution did (recommended). The rule counts only the denials that rules
  made, so main is not stopped. To react to the classifier's denials you set a precaution, which can
  pause main and cannot stop it. It costs a count that can be lower than what you see in the record,
  and Silo has to say so on such a rule.
- A rule may read it, and then only protects. A rule triggered by what a precaution did can alert or
  pause and nothing more. It costs the meaning of "rule": some rules could do anything you wrote and
  others could not, and you would have to know which is which.

Recommended: a rule ignores what a precaution did. Otherwise an opinion, which can be wrong, stops a
computer through a rule, and a stop ends programs that nothing brings back.

That a classifier gave an opinion (which classifier, which version and when, not what it
thinks), or that a precaution acted (which one, and what it rested on), is itself recorded as a
control fact. The opinion's content stays apart from the record. A rule triggered by such a fact
would turn an opinion into a grant by a detour.

## The sentence put forward

"No rule is triggered by a fact that says a classifier gave an opinion or a precaution acted."
Its checks would be the test that runs the real core on every sequence of a few calls, and the simulator.

## Its flaw

It does not cover a rule that counts facts. "Five denied connections in a minute: stop the
computer" would count denials that a precaution made, so an opinion could stop a computer.
