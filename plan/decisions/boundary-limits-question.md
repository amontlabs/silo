# Limits at the boundary

## For the owner

An agent's part, 22 November 2026. A feature proposes a spending limit kept by a small program
inside the computer. An agent with `sudo` can end that program.

The options:

- A principle (recommended). Every addition is asked whether a limit it sets rests on something
  inside the computer. This one does, so it is redesigned. It costs one more question that every
  addition has to answer.
- A decision only. The sentence still binds, as it does today. It costs the question: a limit kept
  inside looks like any other limit until an agent removes it.

Recommended: a principle. Full access inside is the product, so a limit kept inside is not a limit.

The sentence is in force: `where-limits-are-set`. The question is worded by whoever wrote the
plan.

Once it is taken, `inside-cannot-change-rules` and `inside-cannot-change-precautions` follow from it:
their writer named it in `from`, which waits until the principle is in force.
