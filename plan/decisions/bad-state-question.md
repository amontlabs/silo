# No bad state

## The choice

An agent's part, 22 November 2026. A precaution must never grant. Either the app has no way to write
one that grants, or something has to catch it afterwards.

The options:

- A principle (recommended). Every addition names the state that must never exist and what keeps it
  from being written. It costs one more question that every addition has to answer. It also costs
  design work up front, and some states can only be refused when checked.
- A decision only. The sentence still binds, as it does today. It costs the question: a new feature
  can add a state that makes no sense, and a check that someone remembers to write is all that
  catches it.

Recommended: a principle. The sentence is in force, and it only works if it is asked while a feature
is designed.

## Notes

The sentence is in force: `bad-state`. The question is worded by whoever wrote the plan.
