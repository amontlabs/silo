# Does Silo know which calls change something elsewhere

## For the owner

An agent's part, 22 November 2026. You are about to restore main to 14:00. You want to know what the
agent did after 14:00 that a restore cannot undo, such as an email sent or a pull request merged.

The options:

- Listed, as opinions (recommended). Silo lists the calls that changed something elsewhere, and says
  the list is an opinion. It costs some trust in the list: it can miss a call or include one
  wrongly, because Silo cannot see what a call changed on someone else's server.
- Not listed. You read every call after 14:00 yourself. It costs you that reading each time you
  restore.

Recommended: listed, as opinions. A list that says how sure it is beats no list, and it is what a
restore needs.
