# What a receipt is

## The choice

An agent's part, 22 November 2026. claude #1 worked for 1 h 12 in a fork and ends with "Refactored
the parser, all tests pass". You want to know in a minute whether to trust it.

The options:

- Silo writes it from the record (recommended). The receipt lists what Silo saw and was told: the
  commands and their exit codes, the files changed, the hosts reached and what was spent. A test run
  that failed shows as failed, whatever the agent says. It costs the agent's reasons, which the
  record does not hold. They can be shown beside the receipt, marked as the agent's, which is a
  question of its own.
- The agent writes it. Silo shows the agent's own summary, as agent programs already do. It costs
  the check: an agent with full access can write anything, and a summary is often written to please.

Recommended: Silo writes it from the record. You called the receipt the main thing Silo gives, and
it is worth that only if the agent cannot shape it.

## Notes

The owner called the receipt the core of what Silo gives.

The design record states these sentences with no mark, so they are not in force. The meaning of
the word `receipt` is worded from them.
