# Silo

Silo is built one feature at a time. This repository holds its plan, the public site and the code
of the features built so far.

## Context

What an agent reads steers its work, and it can hold only so much. So every file here is small
and is read only for the work that needs it. When you write for an agent (a brief, a guide, an
entry of the plan):

- give it everything the work needs;
- leave out what is wrong, stale, confusing or not needed;
- say each thing in one place.

## Agent workflow

Rules for every agent. Orchestrator: also read .atelier/rules/ORCHESTRATOR.md. Workers: your task says what to read.

1. No CI waits: never push to wait for CI, never poll or rerun it.
2. Run only the tests that prove your change or find what broke. The full check runs when the orchestrator merges; never run it yourself.
3. A failing test is red; nothing is retried. A test that fails and then passes on the same tree is flaky: report it.
4. Only the orchestrator starts reviews, approves and merges.
5. Block, do not poll: never end a turn to wait for a long command.
6. Clean up as soon as nothing depends on it.
7. Your final message is the whole report.
8. These rules live in the repository; do not save them to memory.

## Silo
- Nothing is built without a feature the owner took (`"verdict": "take"` in its file).
- Never write `verdict` or `built` by hand: `plan decide` and `plan finish` do, and the owner's click on the Workshop arrives as a commit.
- `plan/decisions.json` holds what the owner settled for the whole product, and a feature's notes hold what was settled for that feature. They exist so that nobody decides the same thing twice or differently: do not decide it again, and do not report as a problem what they settle. This binds reviewers too.
- Business material (prices, customers, funding) lives in Linear and never in this repository, which is public. Material for the owner alone (advice, things to read, people to ask) goes there too, as an issue in the project "Insights" assigned to the owner. Linear holds nothing else: product ideas and features go in `plan/`.
- Agents are chosen by role name from `atelier agents`, never by provider model; `cheap` only when the owner asks.
- A test that fails and then passes is a fix item, not a retry.
