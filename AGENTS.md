# Silo

Computers your agents can fork. Silo is built one feature at a time. This repository holds the
plan, the public site, and the code of the features built so far.

- `plan/` is the plan: what Silo is (`PRODUCT.md`), every feature (`features/<id>.json`, notes in
  `<id>.md`), their order (`order.json`), the parts of the product (`areas.json`) and the
  decisions in force (`decisions.json`). Plain files: read them, and edit a feature in its own files.
- `website/` is the home page and the Workshop, which shows the plan live. GitHub issues hold the
  conversation: one issue per feature, with votes, comments, the owner's verdicts and the history.
- `tools/plan/bin/plan` does what touches GitHub or more than one file. `plan` alone lists its commands.
- `tools/ci/check.sh` is the whole check. The merge gate and CI both run it.
- [`WRITING.md`](WRITING.md) is how text for a visitor or a user is written (the site, the README, the
  words of the app). Read it before you write any; other work does not need it.
- [`INTERFACE.md`](INTERFACE.md) is how a page or a screen is built (the site, the Workshop, the
  app). Read it before you build any; other work does not need it.
- The old code is not here. It is frozen at the tag `legacy-2026-11-16` and checked out in
  `~/code/projects/silo-legacy`. Only an agent sent for one lookup opens it.
- The research of November 2026, behind most of the lines proposed in the features' notes, is not
  here. It is in `~/code/projects/silo-research`, where
  `2026-11-16-engine-and-product-insights/triage/final/placed.json` names the sources of each line.
  Only an agent sent for one lookup opens it.
- Work on MicroSandbox or libkrun itself (a bug we found, an upstream PR) happens in
  `~/code/projects/msb-upstream`. Read its `AGENTS.md` first; other work does not need it.

Use Node.js 26.

## Agent workflow

Rules for every agent. Orchestrator: also read .atelier/rules/ORCHESTRATOR.md. Workers: your task says what to read.

1. No CI waits: never push to wait for CI, never poll or rerun it.
2. Run only the tests that prove your change or find what broke. The full check runs when the orchestrator merges; never run it yourself.
3. A failing test is red; nothing is retried. A test that fails and then passes on the same tree is flaky: report it.
4. Only the orchestrator starts reviews, approves and merges.
5. Block, do not poll: never end a turn to wait for a long command.
6. Clean up as soon as nothing depends on it.
7. Your final message is the whole report.
8. These rules live in the repository; do not save them to memory.

## Silo
- Nothing is built without a feature the owner took (`"verdict": "take"` in its file).
- Never write `verdict` or `built` by hand: `plan decide` and `plan finish` do, and the owner's click on the Workshop arrives as a commit.
- `plan/decisions.json` holds what the owner settled for the whole product, and a feature's notes hold what was settled for that feature. They exist so that nobody decides the same thing twice or differently: do not decide it again, and do not report as a problem what they settle. This binds reviewers too.
- Business material (prices, customers, funding) lives in Linear and never in this repository, which is public. Linear holds nothing else: product ideas and features go in `plan/`.
- Agents are chosen by role name from `atelier agents`, never by provider model; `cheap` only when the owner asks.
- A test that fails and then passes is a fix item, not a retry.
