== Notes from the probes made while building this check (2026-11-10, Dev engine, e2e-t14-* computers, dropped)
Not produced by the script above; typed from the probe output.
- Guest disks of a new Linux computer: `/` is an overlay (lower: /.msb/rootfs/lower, upper: /.msb/rootfs/upperfs/upper);
  `/workspace` is ext4 on /dev/vdc. The overlay's writable layer is the ext4 disk /dev/vdb (named by "device_id" in
  /.msb/root-disk.json), mounted by the guest init outside the namespace commands run in. `fstrim /` therefore fails
  ("the discard operation is not supported"); mounting /dev/vdb a second time and trimming that mount works
  ("9.7 GiB (10447319040 bytes) trimmed"), and `fstrim /workspace` works. All three virtio disks report discard support.
- Layers of a fork (sandboxes/<fork>/): upper.ext4 (10 GiB raw, a hard link shared with the source), upper-sealed-001.qcow2
  (the source's writes up to the fork point) and upper-restore-<id>.qcow2 (the fork's own head). The marker written to a
  login file in the source was found, byte for byte, in upper.ext4 and in upper-sealed-001.qcow2 (shared, read-only), and
  again in the head after the file was removed and the disks trimmed (the head grew from 5.5 MB to 18 MB; msb does not
  free qcow2 clusters on discard).
- `msb snapshot export` has --with-parents, --since and --last-layers but no way to flatten a chain, so the layers a fork
  shares with its source are written whole: the default export in the run above carries the marker in
  layers/*.raw (the root disk base), layers/*.qcow2 (the head) and snapshots/*/layers/*.raw (the workspace disk base).
