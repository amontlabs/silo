## Evidence

`github-scope`:

- Policy from `github.state` for `silo-eval-a`: `repositoryMode: selected`, one
  repository with `allowPushes: false`, `authenticationMethod: oauth`.
- Exit codes inside the guest: `git ls-remote` of the read-only repository `0`; of the
  ungranted repository `128`; push to the read-only repository `128`; push to the
  ungranted repository `128`.
- The guest's GitHub token was the placeholder `$MSB_SILO_GITHUB`, and the git
  credential helper returned a password starting `$MSB_SILO_GI`. No GitHub-token-like
  string was found anywhere in the guest.
- No push succeeded, and `git ls-remote` on both repositories afterwards showed no
  `silo-eval-*` branch.

`engine-socket`: socket `~/.silo-dev/engine.sock`, owner uid 501, mode `0600`; folder
mode `0700`; eval uid 501.

## Run notes

- Not covered: the cross-user attempt (`--other-user`), because `sudo` on the test Mac
  requires a password.
- The engine's first build answered "GitHub connection is not configured in this
  build". `silo-engine` reads the GitHub App's slug and client credentials at compile
  time (`option_env!`), but only the UI crate's `build.rs` loads them from
  `github-build.local.json`, so `cargo build -p silod` produces an engine without
  GitHub unless the variables are exported. The engine was rebuilt with them exported;
  this packaging gap is tracked separately.
- `engine.credentials.repair` was needed again before the existing GitHub sign-in
  could be read from the Keychain by the new ad hoc–signed build.
- Repository names are left out of this report because they are private.
