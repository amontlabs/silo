# Release artifacts

Names come from `.github/workflows/{release,release-platform,publish-release,engine-release,guest-image}.yml` and `app/SiloUI/scripts/{publish-release,package-engine}.py`. Sizes are not listed: none were measured for this release.

## Build Silo release (`release.yml`, tag `v*` or dispatch)

Release assets on the GitHub release `v<version>` (created as a draft by `publish-release.py`, made public by **Publish verified Silo draft**):

| Asset | Built |
| --- | --- |
| `Silo-macos-arm64.dmg` | CI (macOS runner); locally only as an unsigned or ad-hoc build |
| `Silo-macos-arm64.app.tar.gz` (updater archive) | CI |
| `Silo-macos-arm64.app.tar.gz.sig` (updater signature) | CI, with `TAURI_SIGNING_PRIVATE_KEY` from `release-signing` |
| `latest.json` (update feed read at `releases/latest/download/latest.json`) | CI, generated by `publish-release.py` in the draft job |
| `SHA256SUMS` | CI, same step |

Workflow artifacts (7-day retention, not release assets):

| Artifact | Built |
| --- | --- |
| `release-<asset>` (the files above before the draft job) | CI |
| `runtime-cache-<target>-<run id>-<attempt>` (allowlisted public runtime inputs) | CI |
| `runtime-timings-<target>`, `native-timings-<target>`, `package-timings-<target>` (timing metrics only) | CI |
| `macos-15-library-constraints` (`results.json`) | CI |

The DMG and archive are Developer ID signed and notarized only in `developer-id` mode: a draft with all seven Apple secrets configured. A draft without any of them, local builds and `dry_run` are signed ad hoc and not notarized ([unsigned releases](../../SiloUI-RELEASES.md#releases-without-developer-id-signing)).

## The `silo` command in the app

Local builds: `build_desktop.py` builds `silo-cli` with `silod` (same profile) and copies `silo` to `Contents/MacOS/silo`. Release builds: `release-platform.yml` runs `cargo build --locked --release -p silod -p silo-cli`, and `package-macos-release.py --cli <silo>` copies it into `Silo.app` before `sign_helpers`. Production signing (hardened runtime, no entitlements, identifier `org.silo.cli`; Developer ID and notarized in `developer-id` mode) is checked by `verify_bundle` and `verify_engine_contents`, which fail when `silo` is missing, lacks hardened runtime or carries entitlements. Dev builds keep an ad hoc signature. `embed_engine.py` copies it beside `silod`. On every start the engine links it as `~/.local/bin/silo` (`silo-dev` for Silo Dev), whether or not Connections are on; see [the CLI guide](../../SiloUI-CLI.md#install). It is inside the DMG and the updater archive, not a separate release asset.

## Publish Silo engine (`engine-release.yml`, tag `engine-v*` or dispatch from `main`)

Workflow artifact `silo-engine`, then GitHub release `engine-v<version>` (not marked latest):

- `silo-engine-<version>-macos-arm64.tar.gz` (holds an unsigned `silod`; the embedding app signs it)
- `silo-engine-<version>-macos-arm64.tar.gz.sha256`

CI. Locally: `python3 app/SiloUI/scripts/package-engine.py --out-dir <dir>` writes the same two files.

## Publish Silo guest image (`guest-image.yml`, dispatch or `publish-guest-*` branch)

GitHub release with the tag and title derived by `build-guest-image.mjs metadata`: `image-arm64.tar.gz`, `image-amd64.tar.gz`, `manifest-arm64.json`, `manifest-amd64.json`, `Dockerfile`, `setup-github.sh`, `silo-accessibility.py`, `silo-cua-driver-mcp`, `cua-driver-shim`, `desktop-streamer-lock.json`, `cua-driver-lock.json`, `desktop-packages.txt`, `guest-third-party-notices.md`, `source-commit.txt`, `SHA256SUMS`. Plus OCI images on `ghcr.io`: `<image>-arm64`, `<image>-amd64` and the multi-architecture `<image>`.

CI (needs QEMU for the arm64 build). Locally: `node app/SiloUI/scripts/build-guest-image.mjs arm64|amd64`.
