The `silo` command line and its MCP server no longer read a `.silo` folder, `silo.yaml` or `recipe.yaml`. Recipes now live in Silo itself: store one with `silo recipe add <file>` (the same YAML, with `quiet`, `scrub`, `keep` and `test` in the same file; `silo recipe list`, `show` and `remove` manage them), then use `silo up --recipe <name>` or `silo fork <new-name> --recipe <name>`. A computer remembers the recipe it was made from, its forks inherit it, and a merge adds the packages and settings files it brought to that computer's recipe on its own. If you used `.silo/silo.yaml`: `auto_keep`, `fold: auto-code`, `fork_secrets`, `fork_ram_budget`, per-agent settings and the allowed-devices list are gone (agents now ask you in Silo, and the device warns when it is running short); step checkpoints are `silo exec --step-checkpoints`. The OpenClaw and Hermes recipes and the hosted reviewer are set aside. `silo fold` is now `silo merge` (`silo fold --promote` is `silo replace-main`); an old script prints what to change. A merge that finds a clash lists each one with an id and exits with code 3; run it again with `--choose <id>=fork|main|branch`. Inside a computer, a command that needs your answer prints what it asked and waits two minutes (`--wait`, `--no-wait`, `--reason`); `silo approvals status|wait|note` follows it, and the MCP tools return "waiting for the person" with the request number after a bounded wait. New commands: `silo resources`, `silo access`, `silo restore`, `silo agents`, and `silo fork` now starts the fork unless you pass `--no-start`.
