Silo Help

Silo gives agents computers: isolated Linux environments for development on macOS and Linux. A computer has its own operating system, files, and resources, and is sandboxed from your device. Its workspace is the /workspace folder and disk. Computer disks remain separate from the Silo application.

Computers and the computer page

Use Add above the computer list to create a computer, connect a device, or choose Import computer…. Choose a computer's name to open its page. Drag a computer by its handle, or focus the handle and press the arrow keys, to change its place in the list. This device keeps its own order, for its computers and those on other devices; computers that need attention stay at the top. The page header provides Terminal, Editor, and start or stop controls. Stopping or restarting a running computer asks for confirmation.

The computer page has an Overview tab for settings, secrets, and ports; Checkpoints for saved checkpoints; Storage for local disk usage; and SSH for supported computer connections. Tabs appear only when the computer supports them.

Use the computer's actions menu to edit its settings in place. Duplicate settings copies settings into a new empty computer. On devices with built-in computer use, the new computer includes a desktop that starts automatically with the computer, even if the original used manual desktop startup. Fork… creates a new computer with a copy of this one's files, starting from its current state. A fork is stopped until you start it. CPU and memory edits stop a running computer and apply on its next start. Existing computer names and disk sizes cannot change.

Delete… asks you to confirm permanent deletion and explains which files and checkpoints will be removed. Stop a running computer first. Where offered, Export, then delete saves and verifies an export file before deleting the computer. Delete permanently deletes it without an export.

Overview: secrets and ports

The computer page's Overview tab shows its settings, assigned secrets, and ports. Manage credentials in Secrets and choose which computers and HTTPS domains can use them. GitHub repository access and Git identity are configured in GitHub. Check the operation result; Silo tells you when a change requires a restart.

Network shows ports across computers. A website port opens at an address of its own computer, such as http://dev-1a2b3c4d.localhost:43000, so its cookies stay separate from other local services and computers. Safari needs macOS 26 or later to resolve these names automatically; on earlier macOS versions, choose Chrome or Firefox in Settings. Use Copy 127.0.0.1 address if your browser cannot resolve the computer's address or your development server rejects other host names. The 127.0.0.1 address shares its cookie host with other local services and computers. A computer's website can still send requests to other services on this device, so open it only when you trust its code.

Checkpoints, Fork, and Restore

Open the computer page's Checkpoints tab. New checkpoint captures its current session and disks. Restore rewinds the same computer to a checkpoint after saving a recovery checkpoint. It leaves the computer stopped. Restore does not undo changes outside the computer, such as pushed commits or sent requests.

Use a checkpoint's actions menu to choose Fork… and create a new stopped computer with a copy of its files, or Export… to save a local checkpoint to an export file. Checkpoint history remains on the device that owns the computer.

Delete checkpoint data in Silo on the computer's owning device: choose Delete… in the checkpoint's actions menu when available, then confirm. When viewing a computer on a connected device, open Silo on that device to delete its checkpoints. Delete can be unavailable if this is the latest state the computer builds on, or if later checkpoints, exports, or another computer still need it. Read the reason shown beside the checkpoint. Deleting a computer removes checkpoint data that nothing else needs; retained data is released when its remaining dependencies are removed, which can include deleting a dependent checkpoint. The Storage tab shows checkpoint disk usage.

Export and Import

Choose Export… from a local computer's actions menu and pick a folder to save a .silo-backup export file containing its disks. A running computer keeps running. Checkpoint history is not included. Import creates a new stopped computer from the exported disks, without the captured memory session.

Choose Add then Import computer… above the computer list, or File → Import Computer… in the application menu. Select an export file; Silo verifies it and asks for a computer name. Import does not replace an existing computer. Keep export files off the owning device for another copy, or import one on another compatible device to move your work.

Storage and files

Open a local computer's Storage tab to compare workspace space allocated on this device with space used inside the computer. Workspace storage holds /workspace; runtime storage holds the operating system and installed tools. Deleted workspace files can leave unused space allocated in the disk image. Start the computer and use Free up space to release it without deleting files. Reclamation releases unused allocated space on this device; workspace capacity and files stay the same. It does not reclaim runtime storage or checkpoints. If Silo asks for a restart, restart before reclaiming.

Silo also frees space automatically after seven days since the last success, and before a normal stop when the last success was at least 24 hours ago. A computer without a previous successful reclaim is eligible on its next start. Failed automatic attempts wait at least 24 hours before retrying. Quit gives reclamation a shared 15-second command budget across local computers; a failed reclaim does not prevent normal shutdown.

After an upgrade that converts your computers to new storage, Silo keeps the previous storage as a pre-upgrade backup in case something looks wrong. The migration screen shows its size and the date Silo deletes it automatically, 14 days after the upgrade. Open Settings → General → Storage to see it again: Show reveals the folder in your file manager, and Delete now deletes it permanently after you confirm. The folder holds Linux disk images, so you can copy it elsewhere but not browse files in it. Downgrading to an earlier Silo is not supported. The backup is deleted only after every computer was converted; if you chose to continue after a failed migration, Silo keeps the original computer data and never deletes it.

Files browses computer directories. Start the computer before browsing its files. Point at a folder and choose Upload files here to send files from this device to it, or point at a file and choose Download to save a copy on this device. Uploads go to /workspace folders or the computer's Downloads folder; downloads come from those two places. If a file with the same name is already there, Silo asks whether to replace it or keep both. Transfers handle single files up to 4 GB, 8 GB per upload, and one transfer runs at a time; use Cancel in the notification to stop one. Folders, links, and file names containing * ? [ ] { } \ are not downloaded yet. Transfers need the OpenSSH sftp client that comes with macOS and most Linux systems.

SSH access

Open the computer page's SSH tab, from its ⋯ menu or by clicking its SSH badge, to review connections and authorized keys. SSH from the owning device and SSH from other devices are separate settings. Allow SSH from other devices exposes the selected address and port to that network and asks for confirmation. Only authorized keys can sign in. Use Copy terminal command or Save key file in the connection's actions menu. A downloaded key file is private; keep it secure.

Linux desktop and computer use

New computers on a device with built-in computer use include a Linux desktop for agents (Claude Code, Codex, Pi, OMP and Hermes). Nothing needs to be added: the desktop starts with the computer, and Open Linux desktop opens its viewer. These computers' Edit form does not offer Add Linux desktop or Start desktop with computer.

ChatGPT for Linux. Silo downloads ChatGPT for Linux from OpenAI so agents in your computers can use the Linux desktop. It happens by itself, in the background, on every device that runs Silo: nothing to accept, and creating or starting a computer never waits for it. The download is about 450 MB (about 1.5 GB on disk) once per device, shared read-only by that device's computers; Silo does not install it inside them. If it cannot reach OpenAI (offline, or a firewall holding Silo's connection) it tries again later by itself. Settings → Connections shows nothing about it while it works. If the download fails, or Silo cannot read its state on a connected device, a Computer use components section names that device and the reason and offers Retry or Refresh.

Computer use section. The computer's Overview page shows only the Allow without asking switch. A short line with Try again or Retry appears only when setup or the ChatGPT download fails; hover it for the reason.

Allow without asking is off by default, and Settings → Connections has the switch Allow agents to use the desktop without asking in new computers, which sets what computers you create or import start with (also off by default; computers on a connected device included). Duplicates keep their source's choice, and an imported archive never carries one. Claude Code and Codex then ask before using the computer, as they do for other tools. Pi and Hermes have no such approval and OMP does not prompt by default, so the switch changes nothing for them unless you set OMP to ask. Turn it on and the agents that ask stop asking in this computer. It affects only this computer and its computer-use actions; it does not limit what an agent can do in accounts you are signed in to inside the computer, such as in a browser. The switch works while the computer is stopped. Silo applies a change in the background and shows Applying… until it is done; if it fails or only some agents change, the section says so and warns that some agents may still act without asking, and Silo tries again when the computer starts. The switch configures the agents' approval prompts and is not a security boundary inside the computer. If Silo cannot read the setting, it says so and disables the switch until it can. Other tools keep their own approvals.

Agents are set up automatically. Computer use is registered for every supported agent, including Claude Code and Codex before they are installed and Pi, OMP and Hermes as soon as you install them in the computer. Nothing to run or click: Silo registers a newly installed agent within moments while the computer runs, and at the next start otherwise. Reconnect or restart the agent's session afterward so it loads computer use.

Sound and screen size. The viewer shows a speaker button when this device can play the computer's sound; it is expected to be missing on macOS 14 and 15. Muting is remembered for each computer on this device, and the computer stops sending sound while the viewer window is hidden or minimized. The computer's screen follows the viewer window's size a moment after you resize it. Closing the viewer leaves the screen as it was; choose Reset to 1440×900 in the viewer's actions menu to set it back (resizing the window afterwards makes the screen follow the window again).

Linux desktop in older computers

Computers created before computer use was built in keep the optional desktop described here. The built-in, automatic computer use above needs a new computer; older computers keep the manual Set up LCU path below, which installs the legacy LCU 0.4.0.

Select Linux desktop when creating a computer, or choose Add Linux desktop from an existing computer's actions menu. Installation adds Xfce to the same Ubuntu computer; files and terminal tools stay in place. Desktop packages remain installed.

Start desktop with computer is on by default. Turn it off to start the desktop explicitly from its viewer. Turning it off leaves an existing session running. Stopping the computer always stops its desktop. An explicit desktop stop lasts until you start it again or the computer next starts with automatic startup enabled. If the viewer offers Update desktop instead of Start desktop, keep the computer running and the desktop stopped, choose Update desktop, then Start desktop. Updating the desktop does not start it automatically.

Open Linux desktop opens the interactive viewer. Drop files from this device onto the viewer window to upload them to the computer's Downloads folder; the toolbar shows progress and a name that already exists is kept alongside the new file. Closing the viewer leaves applications running. Stopping or restarting the desktop closes graphical applications, so save your work first. Independent terminal jobs continue. Install additional Linux applications from the desktop terminal; the silo account has passwordless sudo.

Adding a Linux desktop does not install agent tools. LCU is the supported computer-use integration: choose Set up LCU in a running desktop to configure a detected Pi, Codex CLI, or Claude Code installation. LCU requires the official ChatGPT Linux app to be installed in the computer; it does not install or authenticate agent clients. Silo does not coordinate agent input. Applications in the computer can access display :1 as silo. Older computers require migration or recreation before account access. Terminals, SSH, editors, and desktop applications share this account; use sudo for administration. An SSH project does not automatically redirect a computer-use plugin into the computer.

Logs and activity

Logs searches retained history for the selected computers, including stopped computers. Add source or date filters to narrow the search and remove their chips to reset them. Scroll the list to fetch more matching records. Expand an individual record to read its complete fetched text. Follow refreshes recent output; Pause lets you inspect it. Activity shows computer operations and their results.

Silo keeps logs for at most seven days, with separate 125 MiB limits for execution records and runtime/kernel console output per computer (250 MiB total). Console output cannot evict execution records. Oldest segments within each budget are removed first; records in a segment can expire up to a day early. The displayed history boundary tells you what is still available. Device connection errors and expired history are reported separately from log messages.

Copy copies the fetched records with their timestamps and identities. Save logs… saves all matching records, including pages you have not loaded, as a JSON Lines file. You can cancel; an incomplete save does not replace an existing file. Saved files remain yours until you delete them. Review logs for private information before sharing them.

Connections

On the owning device, enable SSH access through the operating system (Remote Login on macOS), then enable Allow connections from other devices in Settings, Connections. On the connecting device, choose Connect device… and paste the displayed address. Both devices must run the same Silo version; update the one with the older version. Keep Silo running on the owning device. Its GitHub account, secrets, exports, and imports remain managed there.

An offline device shows its computers' last known status. Reconnect before changing them. During an update, wait for fresh status before starting another operation.

Menus, navigation, and settings

On Linux, click Menu in the window toolbar, tap Alt, or press F10 to reveal the application menu. Use arrow keys to navigate and Escape to dismiss it. On macOS, use the menu bar at the top of the screen.

Search or Jump To… (⌘K on macOS, Ctrl K on Linux) finds pages, available computer actions, and update actions. The Go menu provides direct navigation. On macOS, open Silo → Settings… (Silo Dev → Settings… in Silo Dev), or press ⌘,, to configure startup behavior, preferred applications, notifications, appearance, and the pre-upgrade backup under Storage while one exists.

Closing the main window leaves Silo running when a status icon is available; otherwise it quits. Open Silo returns to the main window. Quit stops local computers and preserves their disks. Computers on other devices keep running. When local computers are running, confirm with Quit and stop. A shutdown failure keeps Silo open with an error.

Updates

These update instructions apply to the production Silo app. Silo Dev has no update feed and does not install production releases. With automatic checks enabled, Silo checks shortly after launch, when you return to Silo, and daily while open; failed checks retry automatically. Turn automatic checks off in Settings if needed. Silo → Check for Updates… opens Updates and checks for a release. You choose when to download and install. Save work before confirming an update that stops running computers. Silo restarts those computers after updating. A failed check does not mean your version is up to date.

Linux AppImage installations support in-app updates. Debian installations enrolled in Silo's software source offer Update inside Silo. Your system asks for administrator authentication; Silo refreshes package information, installs the update, and restarts. If you use Software Updater or install a package outside Silo, quit Silo first. For a manual installation, choose View installers on GitHub, open the release's Assets, and download the installer for your system.

Help with a problem

Read the operation's error and suggested next step. When Details is available, expand it for diagnostics. Use the copy control when one is offered. Check Logs and Activity for the affected computer. Open System issue when Silo reports a system problem. Follow its recovery instructions and choose Retry checks to run the checks again. When reporting a problem, include your Silo version, operating system, and steps to reproduce it. Remove credentials and private information before sharing logs.
